# Python performance lab

Учебное исследование: как заменить повторные проходы по данным одной агрегацией
и проверить, что ускорение не изменило результат.

**Статус:** код выполнен, результаты реального запуска лежат в docs/example-run/.
Замеры относятся к указанному там окружению. Числовой порог ускорения в тестах
не используется: скорость зависит от машины и нагрузки.

## Задача

Есть список заказов (клиент, сумма в копейках) и список клиентов, для которых
нужно посчитать общую сумму. Сравниваются два решения:

| Решение | Работа | Дополнительная память |
| --- | --- | --- |
| scan | Полный проход для каждого запроса: O(N * Q) | O(Q) для ответа |
| indexed | Построение словаря сумм и поиск: O(N + Q) в среднем | O(C + Q) |

N - число заказов, Q - число запросов, C - число уникальных клиентов.
Время построения словаря включено в indexed.

## Запуск

Нужен Python 3.10 или новее. Внешних Python-зависимостей нет.

~~~bash
python3 -m unittest discover -s tests -v
python3 benchmark.py --rows 100000 --requests 100 --repeats 5 --output results/my-run
~~~

Каталог результатов должен быть новым: прошлый запуск не перезаписывается.
В нем появятся CSV с каждым замером, JSON с окружением и сводкой, Markdown-отчет,
текстовые профили cProfile. Память измеряется через tracemalloc отдельно от
основных замеров.

## Методика

1. Детерминированно сгенерировать данные с seed=42.
2. Проверить совпадение результатов методов.
3. Прогреть оба метода.
4. Чередовать порядок методов и сохранить каждый повтор.
5. Отдельно собрать профиль и пик дополнительных Python-аллокаций.
6. Сравнить медианы, минимумы и максимумы; не делать вывод по одному запуску.

Проверка корректности включает отсутствующих клиентов, повторные запросы,
пустые данные и сравнение с независимым простым решением.

## Что важно понимать

- Словарь ускоряет повторные запросы ценой дополнительной памяти.
- Это агрегация в памяти, а не SQL-индекс или распределенная база.
- cProfile сам добавляет накладные расходы, поэтому его время не используется
  для заявления об ускорении.
- tracemalloc показывает отслеживаемые Python-аллокации, а не всю RAM/RSS.
- Если запрос всего один, словарь может оказаться невыгодным.

## Следующие самостоятельные эксперименты

- Сравнить Q=1, 10, 100 и 1000.
- Сравнить N=1000, 10000 и 100000.
- Попробовать более неравномерное распределение клиентов.
- Объяснить, почему память и скорость меняются по-разному.
